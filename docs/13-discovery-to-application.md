## 1. 문제 정의 수정

**내 상황에서 관련 지원사업·행정업무를 찾고, 필요한 일을 쉽게 실행하도록 돕는다.** 사용자 정정에 따라 상황 입력·정보 가져오기를 기본 진입점으로 둔다. 아래 SNS 발견 과정은 현재 생활의 관찰이며 필수 제품 흐름이 아니다.

초기의 ‘정보 접근 부족’이나 ‘배우자가 행정에 참여하지 못함’만으로는 이번 경험을 설명하기 어렵다. H01에 따르면 배우자는 SNS·블로그에서 외국인 난임 가구의 사례를 찾고 지원 가능성을 남편에게 전달한다. 약제비 신청을 위해 직접 보건소를 방문하기도 했다. 참여는 이미 일어나며 정보 발견 이후의 해석·실행·문제 해결 부담이 남편에게 집중된다. 배우자 행동은 남편이 전달한 사례이며 아내 직접 인터뷰는 아니다.

필요한 일을 이해하지 못한 상태와 인증·이용 제한이 함께 있었다는 응답을 받았다. 다만 구체적인 제한·기관 답변·방문 미해결 이유는 모른다. 외국인이라는 이유로 거절당했다거나 잘못된 창구로 갔다고 추정하지 않는다.

## 4. 제품 방향과 구현 경계

주된 흐름: **내 상황 → 관련 지원사업·행정업무 → 적용 확인·순서 → 다음 행동 → 막힘 원인·대안 → 처리 현황 확인.**

SNS 정보는 선택적인 참고 입력으로 쓰며 자격·금액·기한의 근거로 쓰지 않는다. AI는 표현을 정리하고 누락 조건을 질문하며 검토된 절차를 설명하는 후보 역할이다. 신청 권한·인증 제약은 제품 설명과 별개로 실제 경로를 확인해야 한다.

개인 잔액·접수 상태를 자동으로 보여주려면 권한 있는 조회 경로와 데이터 연계가 필요하다. 현재 연계는 없다. 확인되지 않은 상태는 ‘미확인’으로 표시하고, 데모용 합성 값이나 사용자의 자기보고를 실시간 기관 조회값으로 표현하지 않는다. 버튼 클릭을 실제 접수·지급 완료로 바꾸지 않는다.

현재 앱은 서초구 **시술 전 신청 준비**만 다룬다. 약제비 청구는 시술 후 별도 단계이므로 현재의 ‘시술 시작 전’ 분기를 우회해 적용할 수 없다. 기존 앱의 자동 검사 통과가 약제비 시나리오 통과를 뜻하지 않는다.

다음 검증 사례는 약제비 청구 한 건을 우선 후보로 삼는다. 사업·관할·실패 사유와 근거를 정리한 뒤 별도 흐름으로 설계한다. 모든 지원사업 자동 신청이나 모든 기관 연동으로 확대하지 않는다.

## 5. 성공·중단 기준

- 자기 상황에서 관련 사업·행정업무와 적용 이유·미확인 조건을 찾는가. 외부 사례를 미리 찾아와야 하지 않는가.
- 다음에 누가 어디에서 무엇을 해야 하는지 스스로 설명하고 수행할 수 있는가.
- 막혔을 때 같은 링크·방문을 반복하지 않고 실패 사유와 구체적 해결 행동을 찾는가.
- 실제 접수 확인까지 남편의 추가 검색·설명 부담이 줄었는가. 자발적 업무 분담을 실패로 보지 않는다.
- 잔액·접수·지급 정보를 모르는 상태를 잘못 확정하지 않는가.

현재 어느 효과도 측정하지 않았다. 인증·기관 처리 제약으로 진행이 불가능하면 그 지점과 필요한 공공 개선을 결과로 남긴다. 설명만 개선하고 신청을 해결했다고 보고하지 않는다.

현재의 근거는 한 가구의 경험과 일부 공식 안내다. 문제의 구체성은 높아졌지만 시장 규모·경쟁우위·유료 수요를 입증하지는 않는다.

## 7. 부모님 경험과 고객 범위

사용자는 부모님의 행정업무도 대신 처리한다고 설명했다. 아내는 쉽고 정확한 방법을 제시하면 직접 수행할 수 있을 것으로, 부모님은 어려울 것으로 예상했다. 부모님이 못하는 구체적 조작·원인이나 모든 시니어의 특성을 확인한 것은 아니다.

공통 문제는 행정 실행에 다른 사람의 도움을 받는다는 점이다. 필요한 해결책은 도움의 수준에 따라 다를 수 있다. 본인 실행 지원과 가족 협력 지원은 같은 자료·절차를 재사용할 수 있지만, 화면·동의·접근·권한 설계는 별도다. 첫 검증은 디지털 사용이 가능한 행정 초심자의 직접 수행에 집중한다. 외국인 가구는 이 문제를 검증할 첫 대상이며 전체 시장과 동일하지 않다.
