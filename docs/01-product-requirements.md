# MARO 제품 요구사항

기준일: 2026-09-18 · 방향 고정 · 사용자 효과 검증 전

현재 범위·수혜·측정·정부 요청의 통합 기준은 [서비스 정의](15-service-definition.md)다.

## 1. 제품 정의

**MARO — My Administrative Roadmap**은 **내 상황을 바탕으로 관련 지원사업과 처리할 행정업무를 찾고, 필요한 행동을 쉽게 수행하도록 돕는 서비스**를 지향한다.

기본 흐름은 상황 입력 또는 동의·권한이 확보된 정보 가져오기 → 관련 사업·행정업무와 적용 확인 → 다음 행동 → 실행·막힘 해결 → 처리 상태 확인이다. 외부 포스트는 선택적인 참고 입력이며 기본 진입 조건이 아니다. 현재 기본 앱은 이 비전 중 한 업무의 실행 로드맵을 구현했다. 기존 서류 준비 비교 도구는 연구용 화면으로 분리했다. [경험·설계 경계](13-discovery-to-application.md)

현재 기본 작동 사례는 금천구 난임 시술 후 약제비 청구 합성 흐름이다. 지원 잔액 확인 → 청구 경로 확인 → 서류 준비 → 접수 → 접수 이후 상태 확인의 5단계를 보여준다. 실제 잔액 조회·제출·기관 상태 연계는 남아 있다. 첫 검증 대상은 디지털 도구 사용이 가능하지만 한국 행정의 조건·용어·순서에서 막히는 사람이다. 최종 자격 판정·전면 신청 대행·개인정보 자동 연계는 현재 구현하지 않았다.

## 2. 문제와 현재 근거

- 공식 자료를 조사한 결과, 기한과 외국인 관련 서류의 적용 범위에 미확인·상충 항목이 있었다. [근거 등록부](08-source-register.md)
- 한국인 남편 응답자 한 명이 난임 지원과 전세대출에서 서류·행정 준비를 맡았다고 설명했다. 배우자의 높은 한국어 능력과 별개로 용어·경험 부족을 이유로 들었다. 내부 기록이며 아내 본인의 응답은 아니다. [H01](research/session-H01.md)
- MY SEOUL+의 출시는 서울시가 정보 탐색·언어 장벽을 정책 과제로 인식한다는 근거다. MARO의 수요나 우위를 입증하지는 않는다. [경쟁 근거](11-positioning-and-evidence.md)

이 자료로 실제 불편의 후보를 찾았지만, 발생 빈도·시간 손실·사용자 선호·제품 효과는 아직 측정하지 않았다.

## 3. 대상과 달성하려는 일

| 대상 | 원하는 결과를 검증할 질문 |
| --- | --- |
| 행정 경험이 적은 외국인 배우자 | 서류의 뜻과 준비 행동을 이해하고 원하는 만큼 참여할 수 있는가? |
| 준비를 맡은 한국인 배우자 | 대신 설명·검색·재확인하는 부담을 줄일 수 있는가? |
| 향후 상담 실무자 | 상황·미확인 질문이 정리되면 반복 설명이 줄어드는가? |

가족이 합의해 한 사람이 처리하는 것을 실패로 보지 않는다. 외국인 배우자가 더 많은 Task를 맡는 것 자체가 목표는 아니다. 국적·한국어 수준만으로 수행 능력이나 역할을 정하지 않는다.

## 4. 검증할 가설

| ID | 가설 | 확인 방법 |
| --- | --- | --- |
| H-TERM | 일상 한국어와 행정 서류 이해에는 차이가 있다 | 실제 용어·서류 사례와 쉬운 설명 후 다음 행동 확인 |
| H-PREP | 공식 안내를 읽고도 자기 상황의 미확인 조건·준비 누락을 놓친다 | 같은 합성 사례에서 찾은 항목 기록 |
| H-PACKET | 조건·질문을 묶으면 동일한 정적 안내보다 준비 판단이 쉬워진다 | 같은 내용 A/B 과제 비교 |
| H-HANDOFF | 상황과 질문 묶음이 상담의 반복 설명을 줄인다 | 후속 실무자 검증; 현재 미실시 |

‘번역만으로 부족하다’는 결론을 미리 정하지 않는다. 쉬운 설명만으로 충분하면 기능을 단순화한다.

## 5. 기존 서비스와의 관계

MY SEOUL+는 비교 대상이자 향후 연결 후보다. 공개 정보·챗봇·상담 예약이 이미 존재하므로 MARO가 정보 접근 문제를 처음 해결한다고 소개하지 않는다. **기존 안내를 이용한 다음, 개인별 준비 과정에서 남은 부담**을 검증한다. 제휴·API 연동·공공기관 채택은 확보되지 않았다.

‘FAQ 대 Task’, ‘번역 대 참여’처럼 기존 서비스를 단순화한 비교표는 사용하지 않는다. 실제 관찰과 한계는 [실행 기록](12-comparative-validation.md)에 둔다.

## 6. 목표 경험과 현재 구현

1. 현재 상황을 말하거나 필요한 최소 조건만 선택한다. 모든 개인정보를 한꺼번에 요구하지 않는다.
2. 검토된 범위 안에서 관련 지원사업과 행정업무를 보여주며 해당 이유·미확인 조건을 설명한다.
3. 지금 할 행동과 나중에 할 행동, 선행 조건을 구분한다. 신청 가능 확정과 후보 추천은 다르다.
4. 업무 하나를 선택하면 서류·인증·화면 선택을 쉬운 단계로 이어준다.
5. 막히면 실패 이유에 따라 확인·대체 경로·도움 요청을 안내한다.
6. 자기보고 진행 상태와 실제 기관 접수·처리 결과를 구분한다.

현재 기본 앱은 자연어형 합성 상황 진입, 5단계 실행 로드맵, 단계별 공식 근거, 막힘 질문을 구현했다. 기존 서초구 합성 조건·서류 구분·문의 준비서는 research.html에 보존한다. 실제 상황별 사업 발굴·개인정보 가져오기·신청 실행·기관 상태 연계는 목표 기능이다. SNS 사례 탐색은 사용자 경험의 관찰이며 필수 제품 단계가 아니다.

### 도움 수준에 따른 대상 구분

| 사용 방식 | 첫 가설 | 제품 요구 |
| --- | --- | --- |
| 본인이 실행 | 쉬운 절차와 정확한 다음 행동이 있으면 수행 가능 | 최소 입력, 쉬운 설명, 한 번에 한 행동, 막힘 해결 |
| 가족과 함께 실행 | 설명이 있어도 조작·인증·지속적인 도움이 필요할 수 있음 | 당사자 동의, 도움 요청, 함께 보기, 권한별 할 일 구분 |

국적·연령으로 사용 방식을 고정하지 않는다. 아내의 독립 수행 가능성과 부모님의 어려움은 사용자의 예상이며 직접 수행 테스트 결과는 아니다. 첫 MVP는 본인 실행을 중심으로 검증하고, 가족 지원 흐름은 후속 대상으로 둔다. 가족 지원이 기관의 대리 신청 권한을 자동으로 부여하지 않는다.

## 7. 성공의 정의

초기 핵심 지표는 **중요한 누락·오해 없이 다음 준비 행동과 확인할 질문을 구성한 정도**다. 같은 정보의 정적 안내보다 나아졌는지와 추가 입력 부담을 함께 본다. 후속 실증은 가구 전체의 활동 시간·반복 설명·준비 누락을 측정한다.

참여율은 당사자가 원할 때의 보조 지표다. 한국인 배우자 단독 수행 비율을 무조건 줄이려 하지 않는다. 서류 확인 클릭·참여 의향·합성 테스트를 실제 행정 완료로 세지 않는다.

## 8. 유지·수정·전환

사용자 검증으로 실제 준비 부담과 도구의 추가 가치를 확인하면 이 사례를 유지한다. 설명만으로 충분하면 단순화한다. 주된 장벽이 인증·법적 권한이면 정책·상담 업무 관점에서 재정의한다. 난임 사례에 접근이 어렵고 다른 사례에서 명확한 부담을 관찰하면 사례를 전환한다. 이미 작성한 문서·코드의 양은 유지 이유가 아니다.

장기 비전은 생활 사건 전반의 행정 참여 지원으로 남긴다. 확장은 자료 검토 책임·업데이트 비용·사용자 유입을 확인한 뒤 결정한다.
