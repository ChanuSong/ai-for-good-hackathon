# 경쟁·가치 검증 실행 기록

기준일: 2026-09-17. 공개 서비스 관찰, 남편의 경험 응답, 기술 검사, 사용자 효과를 구분한다.

## 1. 현재 결론

**주제 유지, 검증 대상 축소:** 서류의 뜻·적용 여부·직접 제출 필요성을 구분하고 공식 준비 경로로 이어주는 경험을 검증한다. 질문 생성 자체는 기존 챗봇에도 있다. 차별성·시간 절감·지불 의사는 아직 입증되지 않았다.

MY SEOUL+의 존재는 정책적 문제 인식과 협력 가능성의 근거다. MARO의 수요·성능 근거로 대체하지 않는다.

## 2. MY SEOUL+ 실제 챗봇 관찰

[공개 포털](https://global.seoul.go.kr/hmpg/main/main.do), 2026-09-17, Chrome·Playwright, 데스크톱, 한국어, 질문마다 새 컨텍스트. 이용 안내 동의를 거쳐 합성 사례만 전송하고 약 20초 후 응답을 읽었다. 각 질문 한 번이며 정확도·재현성 통계는 없다.

### Q1 — 필요한 서류·경로

일본 국적 아내·한국 국적 남편, 법률혼, 남편 주소 서초구, 시술 전 첫 신청 준비라는 가상 조건에서 서류·경로·확정할 수 없는 사항을 질문했다.

신청서·가족관계·진단서 외에 남편 소득증명·신분증 또는 여권 사본을 제시했다. 보건소 방문과 가능한 경우 온라인 신청을 안내하고 금액·기한은 확인하도록 했다.

기본 안내와 불확실성 언급은 있었다. 소득증명 필요성은 이 사례의 서초구 기준 목록으로 뒷받침하지 못했다. 모든 상황에서 틀렸다고 일반화하지 않는다. Q1은 링크 DOM을 수집하지 않아 직접 근거 링크 유무는 판정하지 않는다.

### Q2 — 보험 미확인 시 행동·질문·근거

같은 조건에서 두 사람의 보험 가입·고지가 미확인이라고 밝히고 다음 행동·문의 질문·공식 근거를 요청했다.

보험 확인·창구 방문과 함께 서류, 보험 영향, 미납 영향, 절차·시간을 묻는 질문 4개를 제안했다. 근거 표시는 있었지만 응답 영역의 실제 링크 요소는 0개였다. 외국인 보험 가입과 미납 설명의 개별 적합성은 이번 조사로 확정하지 않았다.

**질문 목록 생성은 이미 가능하다.** MARO의 추가 가치 후보는 서류 구분·직접 근거·실행할 준비 행동이다.

### 한계

다른 언어·로그인·반복 질문·상담원·서비스 전체 품질은 평가하지 않았다. 초기 안내 동의 체크박스 조작 실패 1회는 전송 전 자동화 실패였으며 응답 실패로 세지 않는다. 응답 전문·실제 개인정보는 공개 자료에 복제하지 않았다.

## 3. 경험과 공식 페이지 대조

직접 응답자 1명·1가구·2사건. 난임 지원의 출발 자료로 정부24를 제시했고, 서류별 다른 페이지에서 발급하는 부담을 설명했고, 후속 응답에서 여러 서류를 직접 발급해 제출했다고 확인했다. 목록 전체를 발급했다거나 동의를 전혀 하지 않았다고 해석하지 않는다. 배우자가 수행할 때의 비효율은 남편의 예상이며 측정값이 아니다. [내부 기록](research/session-H01.md)

[정부24 난임 지원 안내](https://www.gov.kr/mw/AA020InfoCappView.do?CappBizCD=14600000394)의 목록에는 공무원 조회 가능 항목이 포함된다. 가족관계증명서는 본인정보 제공 요구 항목으로 따로 안내된다. 원문 변경·확인일은 2025-07-31, 이번 열람일은 2026-09-17이다.

과거의 발급이 불필요했다고 판정하지 않는다. 당시 요구·동의·조회 성공 여부는 추가 확인 중이다. 제품 위험은 목록을 펼치기만 하면 서로 다른 제출 구분을 잃을 수 있다는 점이다. 다만 이 사용자의 실제 발급 원인이 목록 오독이었다는 증거는 없다. 확인된 발급·제출 부담의 어느 단계를 줄일 수 있는지 검증한다.

## 4. 비교 도구

[로컬 프로토타입](../prototype/README.md)은 동일 claim 8개, 질문, 용어 2개, 서류 구분 3종·준비 경로 3개를 사용한다.

- A: 근거부터 읽는 안내 형식.
- B: 서류 구분·남은 확인·질문을 먼저 보는 점검 형식.
- 둘 다 같은 조건 분기를 사용한다. 개인화 유무가 아니라 **배열·표현의 탐색적 비교**다.
- A는 MY SEOUL+의 복제품이 아니며 A/B 결과로 기존 서비스 대비 우위를 주장하지 않는다.
- AI 미연결. 자동 발급·인증·신청·행정정보 조회를 수행하지 않는다.

## 5. 기술 검사와 남은 검증

규칙·데이터 검사와 Chrome 점검을 실행한다. 최종 실행 결과는 아래 기록을 따른다. 자동 검사는 행정 정확성·일본어 의미·사용자 효과 검증이 아니다.

실제 화면 사용자 테스트는 미실시다. 과제는 제출·조회 구분, 직접 제출 필요 시 공식 경로, 미확인 조건을 독립적으로 찾는 것이다. 반복 노출과 진행자 도움을 기록한다.

## 6. 결정 기준

- 유지: 구체적 준비 부담이 있고 점검 화면에서 놓친 중요 행동을 독립적으로 찾으며 새로운 오해가 없음.
- 단순화: 같은 정보의 안내·쉬운 풀이로 충분하거나 추가 입력이 부담.
- 접근 전환: 인증·권한·기관 처리가 핵심이라 안내로 해결되지 않음.
- 사례 전환: 난임의 필요성을 확인하지 못하고 다른 사건에서 반복 문제가 관찰됨.

2명 이하의 관찰은 탐색이다. 현재는 문제 구체화·비교 도구 준비까지이며 시장·효과 검증 완료는 아니다.

## 7. 최종 기술 확인 — 2026-09-17

- 기준 데이터 검사 통과: 초기 출처 2개·claim 8개·Task 6개·수용 명세 12개. 이는 기존 Task 앱 수용 테스트의 통과가 아니다.
- Python 회귀 검사 9개 통과, 현재 준비 규칙 Node 검사 10개 통과.
- Chrome에서 A/B의 claim·질문·서류·내보내기 내용 동일성, 조회 후보 9개·공식 경로 3개, 조건·한일 전환 유지, 범위 변경 시 안내 제거, 초기화·새로고침을 확인했다.
- 인쇄용 전체 텍스트와 문의 준비서 일치, PDF 생성, 390px 가로 넘침 없음, 데이터 로드 실패 안내를 확인했다.
- 해당 브라우저 세션에서 페이지 오류·외부 자동 요청 없음, localStorage·sessionStorage 사용 없음. 공식 링크를 클릭한 뒤 외부 사이트의 동작까지 검사한 것은 아니다.
- 로컬 Markdown 대상 링크·JSON 문법 확인. 데스크톱 화면 캡처 시각 점검.

기술 점검은 실제 사용자의 서류 준비·발급 성공이나 시간 절감 결과가 아니다. 사용자 화면 과제는 여전히 미실시다.

## 8. H01 병목 구체화

후속 선택 응답은 ① 필요 서류 판단, ② 발급 사이트·메뉴 찾기, ③ 로그인·인증·발급 옵션 선택이다. 한 가구의 실제 준비 경험에 대한 자기보고이며 세 단계의 우선순위나 빈도·소요 시간을 측정한 것은 아니다. ③의 세부 원인과 실제 이용 제한 여부는 아직 미확인이다.

현재 프로토타입은 ①의 제출·조회 구분과 ②의 공식 경로 일부를 제공한다. 개인별 필요 서류 판정이나 ③의 실제 화면 안내·인증 성공은 검증하지 않았다. 따라서 링크 연결만으로 세 단계 모두 해결했다고 발표하지 않는다. 검증 과제에 '서류 하나의 준비 경로에서 다음 선택과 막혔을 때의 행동 설명'을 추가하되, 실제 발급은 별도 범위로 둔다.

## 9. 약제비·발견 이후 실행 경험 추가

H01은 안내의 어려움과 실제 이용 제한 모두를 보고했다. 배우자는 SNS·블로그에서 지원을 발견하고 남편에게 전달하며 남편이 절차 조사·실행을 맡는다고 했다. 약제비는 배우자가 보건소를 방문했지만 미해결이었고, 남은 지원금과 확인 경로도 모른다고 했다. 미해결 사유·구체적 제한·개인 잔액은 아직 알 수 없다.

새 가설은 정보 발견 이후의 개인 적용·신청·막힘 해결·진행 확인이다. 서류 하나의 링크 연결만으로 충족되지 않는다. [지역별 공식 자료와 제품 경계](13-discovery-to-application.md)를 추가했다. 사용자 관할로 추정하거나 서초구 데이터에 타 지역 규칙을 적용하지 않았다. 개인 신청·조회·기관 연락·새 앱 기능 구현은 수행하지 않았다.

## 10. 상황 중심 진입과 도움 수준 구분

사용자가 상황 입력·정보 가져오기에서 지원사업과 행정업무로 이어지는 제품 흐름을 명시했다. 외부 포스트는 필수 입력에서 제외했다. 부모님 업무를 대신 처리하는 경험이 추가됐지만 부모님·아내의 직접 수행 능력을 비교 측정한 것은 아니다.

문제는 폭넓게 적용될 수 있으나 본인 실행 지원과 가족 협력 지원의 요구가 다를 수 있다. 첫 검증은 디지털 도구 사용이 가능한 행정 초심자의 직접 수행으로 좁힌다. 맞춤형 안내의 기존 사례로 복지로 복지멤버십 공식 설명을 확인했으며, 추천만으로 경쟁우위를 주장하지 않는다. [설계 근거](13-discovery-to-application.md)

## 11. 호주·캐나다 및 한국 공식 사례 조사
