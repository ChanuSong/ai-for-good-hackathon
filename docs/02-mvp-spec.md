# MVP 요구사항·사용자 경험

기준일: 2026-09-18 · 제품 데모와 검증 도구 분리

## 1. MVP가 증명할 것

SeoulMate의 비전은 생활행정 전반이지만 해커톤에서는 한 업무를 처음부터 끝까지 실행 가능한 흐름으로 연결하는 경험만 검증한다.

첫 업무는 난임 시술 후 원외 약제비 청구다. 이 업무가 모든 외국인 주민의 대표 문제라는 뜻이 아니다. 적용 조건, 잔액, 병원·약국 자료, 보건소 접수 경로가 연결돼 있어 정보 → 실행의 간극을 좁게 관찰하기 적합하기 때문에 선택했다.

제품의 핵심 루프:

상황 입력 → 업무 파악 → 지금 할 행동 → 막힘 해결 → 다음 단계 → 처리 확인

## 2. 발표용 제품 데모

기본 prototype/index.html은 심사위원용 제품 화면이다.

합성 입력 예:

> 시술은 끝났고, 약값도 지원받을 수 있다고 들었어요. 어떻게 청구하나요?

현재 데모는 키워드 기반으로 지원 시나리오를 선택한다. 생성형 AI가 연결된 것으로 소개하지 않는다.

로드맵 단계:

1. 지원 잔액 확인
2. 이용 가능한 청구 경로 확인
3. 약제비 청구 서류 준비
4. 약제비 청구 접수
5. 접수 이후 상태 확인

각 단계에는 다음을 제공한다.

- 지금 할 행동
- 왜 필요한지
- 공식 안내에서 확인할 내용
- 공식 출처
- 막혔을 때 담당 창구에 물어볼 질문

사용자의 확인은 준비 진행 상태일 뿐 기관의 접수·보완·지급 완료를 뜻하지 않는다.

## 3. 공식 자료와 적용 경계

현재 약제비 데모는 금천구 보건소의 2026-02-26 수정 안내를 근거로 한다.

확인한 내용:

- 약제비는 시술 회차별 지원 잔액이 남는 경우 일부 지원됨.
- 개인이 보건소에 청구하는 흐름.
- 방문·이메일·e보건소 경로 안내.
- e보건소 경로는 e보건소에서 시술비 지원을 신청한 경우라는 조건이 있음.
- 청구 기한은 시술 완료 후 1개월 이내로 안내됨.
- 신청인용 청구서, 시술확인서 사본, 원외약 처방전·약제비 영수증, 본인 통장 사본이 안내됨.

확정하지 않는 내용:

- 개인별 남은 잔액
- 개인별 최종 자격
- 실제 온라인 인증 가능 여부
- 추가 서류 여부
- 접수·보완·지급 완료 상태

## 4. 연구용 비교 화면

기존 서초구 시술 전 준비 A/B 화면은 prototype/research.html로 보존한다.

목적은 동일 자료에서 정적 안내(A)와 준비 점검(B)의 정보 탐색 차이를 비교하는 것이다.

이 화면은 SeoulMate의 최종 제품 UX가 아니며, MY SEOUL+를 복제한 비교군도 아니다.

## 6. AI 연결 기준

AI가 필요한 지점은 정책 규칙 생성이 아니다.

후속 AI 역할:

1. 사용자의 자유로운 표현에서 사건과 이미 확인된 조건을 추출한다.
2. 아직 확인하지 않은 조건을 구조화해 최소 질문을 만든다.
3. 검증된 행정 데이터를 사용자의 언어와 수준에 맞게 설명한다.

행정 요건·기관·기한·공식 URL·검증 상태는 모델이 생성하지 않는다. 허용된 사건·조건 ID를 선택한 뒤 앱이 등록 데이터를 조립한다.

구조:

Unstructured intent → LLM extraction → verified workflow/rules → next action → human/institution escalation

## 7. 이번 검증에서 제외

- 실제 정부 사이트 제출 자동화
- 실제 잔액 조회
- 사용자 개인정보·의료서류 업로드
- 가족 역할 배정과 대리 권한
- 모든 자치구의 난임 정책
- 전세대출·이사 등 다른 Life Event
- 실제 기관 처리 상태 자동 동기화

## 8. 성공 기준

해커톤에서는 효과를 이미 입증했다고 말하지 않는다. 다음을 관찰한다.

- 사용자가 첫 화면에서 다음 행동을 설명할 수 있는가.
- 막혔을 때 누구에게 무엇을 물어야 하는지 설명할 수 있는가.
- 서류·경로·잔액 등 미확인 조건을 임의로 확정하지 않는가.
- 사용자 체크와 기관 결과의 차이를 이해하는가.

후속 실증에서는 실제 접수, 보완·재방문, 본인+가족 활동 시간, 담당 창구의 반복 설명을 측정한다.
