# 준비 점검 구현 계약

기준일: 2026-09-17 · 로컬 규칙 기반 비교 도구 구현, AI 미연결

## 1. 구성

- `prototype/engine.mjs`: 합성 조건 검증·범위 분기·질문·문의 준비서 구성.
- `prototype/app.mjs`: A/B·한일·용어 도움·복사·인쇄·초기화.
- `data/seocho-infertility.json`: 기존 공식 claim·출처. Task 6개는 후속 확장 참고이며 현재 UI는 claim을 사용.
- `data/preparation-glossary.json`: 별도 공식 출처를 연결한 쉬운 용어 풀이, 사람·번역 검토 전.

현재 모델 호출·생성 지연·역할 배정·Task 완료는 없다. 초기 AI·로드맵 수용 사례는 기존 `data/acceptance-cases.json`에 참고로 남기며 앱 통과로 표시하지 않는다.

## 2. 합성 조건과 분기

| 필드 | 값 | 처리 |
| --- | --- | --- |
| district | seocho / other / unknown | 다른 지역·모름에는 서초구 신청 절차와 창구를 적용하지 않음 |
| marriage | legal / de_facto / unknown | 사실혼·모름은 현재 법률혼 사례를 적용하지 않음 |
| insurance_confirmed | yes / no / unknown | no·unknown이면 확인 질문 유지, 지원 불가로 판정하지 않음 |
| treatment_started | no / yes / unknown | yes·unknown이면 서초구 범위 내에서 시점 상담만 제공 |
| preparation | not_checked / some_prepared / reviewed | 목록 확인 자기보고; 근거·기한·개인 자격과 무관 |
| language·view·glossary | ko/ja, A/B, on/off | 표현·구성만 변경. 행정 조건을 바꾸지 않음 |

허용되지 않은 값·추가 개인정보 필드를 거부한다. 조건 변경 시 즉시 재계산해 오래된 질문·창구를 제거한다. 두 화면은 같은 engine 결과를 사용한다.

## 3. 근거·자기보고·완료의 경계

- 보험·목록을 확인했다고 선택해도 C-06·07·08의 상충·적용 미확인 상태는 남는다.
- ‘준비 완료’, ‘자격 충족’, ‘지원 가능’ 점수를 표시하지 않는다.
- 질문 개수는 남은 질문 수이며 행정 진행률이 아니다.
- 문의 준비서는 합성 조건과 검토 전 표시를 포함한다. 법정 신청서가 아니다.
- 다른 지역에는 서초구 전화번호를 문의 준비서에 넣지 않는다.

## 4. 데이터 처리

브라우저 메모리만 사용한다. localStorage·sessionStorage·쿠키·DB·외부 분석·AI 전송은 없다. 합성 선택 항목 외 자유 입력과 문서 업로드는 받지 않는다. 초기화·새로고침·탭 종료 시 상태가 사라진다.

복사·인쇄는 사용자 클릭으로 실행한다. 공식 링크 클릭은 외부 사이트 방문으로 이어진다. 로컬 Python 서버는 저장소 파일을 제공하므로 127.0.0.1에만 바인딩하고 인터넷에 노출하지 않는다. 외부 배포 시 내부 조사 문서가 포함되지 않도록 별도 빌드·배포 경계를 설계한다.

사용자 인터뷰 원문은 프로토타입에 포함하지 않는다. 연구 기록의 익명화·보관·인용 범위는 04 문서를 따른다.

## 5. 검증

- `node --test tests/preparation.test.mjs`: 조건·범위·근거 상태·질문 구성 검사.
- 기존 Python 검사는 행정 기준 데이터의 구조·참조·의존관계를 확인한다.
- 브라우저: 동일 내용 비교, 언어·조건 유지, 범위 밖 안내 제거, 초기화, 좁은 화면, 외부 요청·저장 여부, 오류 표시를 확인한다.
- 자동 검사는 행정 판단·번역 의미·사용자 부담 감소를 검증하지 않는다.

## 6. AI를 연결할 때

사용자의 표현에서 조건·질문을 추출하더라도 확인 화면을 거쳐야 한다. 모델이 요건·기한·기관·URL·검증 상태를 새로 만들거나 상충을 임의 해소할 수 없다. 허용 ID만 수용하고 등록 자료로 핵심 문구를 조립한다.

자유 입력을 외부 모델에 전송하기 전에 개인정보 처리·제공자 보존·로그 범위를 확정한다. 키는 서버에 보관하고, 입력 길이·허용값·호출 비용을 제한한다. 실패·지연 시 정적 자료 모드로 명시적으로 복귀한다. 실제 연결 전에는 AI 작동을 주장하지 않는다.

## 7. 서류 준비 지도

`data/document-preparation.json`은 정부24 제출 구분·원문 갱신일·열람일과 준비 경로를 담는다. 기존 claim의 상충 상태를 덮어쓰지 않는다. `documentPlan`은 지원 범위에서만 제공하고, A/B와 문의 준비서에 같은 내용을 쓴다.

조회 가능 후보는 필수 발급이나 면제 확정이 아니다. 현재 앱은 개별 서류의 적용 판정·정보제공 동의 접수·실제 조회·발급을 하지 않는다. 확인된 경로 3개도 로그인 후 수행 완료를 검증한 것은 아니다. 인쇄는 전체 문의문을 줄바꿈 가능한 텍스트로 출력한다.
