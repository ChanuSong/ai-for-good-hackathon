# MARO 준비 점검 비교 프로토타입

목적: 같은 정보의 정적 안내(A)와 조건·질문을 묶은 준비 점검(B)의 가치를 비교한다. AI는 연결하지 않았다. 합성 조건만 사용하며 브라우저 메모리 외 저장·외부 분석·외부 AI 전송이 없다. 클립보드 복사·인쇄는 사용자가 누를 때만 실행한다.

프로젝트 루트에서 실행:

```sh
python3 -m http.server 8973 --bind 127.0.0.1
```

브라우저에서 `http://127.0.0.1:8973/prototype/`를 연다. A부터 시작하며 `?view=B`를 붙이면 B부터 시작한다. 이 서버는 **로컬 작업용**으로 저장소 전체를 제공하므로 인터넷에 공개하지 않는다. 외부 배포·공유 링크는 아직 없다.

- 기준 자료: `data/seocho-infertility.json`의 동일한 claim과 출처.
- 조건이 범위 밖이면 서초구의 신청 준비 안내를 중단한다.
- 사용자가 목록을 확인했다고 해도 출처 충돌·적용 불명확·개인별 자격은 해소되지 않는다.
- 언어 전환·A/B 전환은 선택 상태를 유지한다. 전체 초기화·새로고침은 기본 합성 상태로 돌아간다.
- 문의 준비서는 합성 사례라는 표시와 미검토 상태를 포함한다. 법정 서식이나 실제 신청서가 아니다.
- 정적 안내 A는 MY SEOUL+를 재현한 것이 아니다. 이 비교로 기존 서비스 대비 우위를 주장하지 않는다.
- 일본어는 초안이며 사람 검토 전이다.
- 쉬운 용어 설명은 양쪽에 동일하게 제공한다. 설명만으로 충분한지 먼저 살핀 뒤 A/B 구성 차이를 비교한다. 용어 설명을 한쪽에만 켜고 구성 효과로 해석하지 않는다.

자동 규칙 검사: `node --test tests/preparation.test.mjs`. 사용자 결과와 별개다.

서류 준비 지도는 정부24의 제출·조회 구분과 공식 준비 경로 3개를 연결한다. A/B 모두 동일한 내용이며 B는 서류 준비를 근거 설명보다 먼저 보여준다. 실제 면제·조회 성공·발급을 판단하지 않는다. 인쇄에는 전체 문의 준비서와 서류 구분·경로가 포함된다.
