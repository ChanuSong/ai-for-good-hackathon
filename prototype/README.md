# SeoulMate 프로토타입

기본 URL은 심사·발표용 제품 데모다. 기존 A/B 비교 도구는 연구용 화면으로 보존한다.

## 실행

프로젝트 루트에서 다음 명령을 실행한다.

    python3 scripts/serve_preview.py --port 8973

- 제품 데모: http://127.0.0.1:8973/prototype/
- 연구용 비교: http://127.0.0.1:8973/prototype/research.html?view=B

미리보기 서버는 prototype·data의 허용된 정적 파일만 제공하며, .env·Git·내부 문서·디렉터리 목록은 차단한다.

## 제품 데모

금천구 보건소의 공식 난임부부 시술비 안내를 근거로 한 합성 약제비 청구 시나리오다.

상황 입력 → 실행 로드맵 → 지금 할 행동 → 막힘 질문 → 다음 단계 → 처리 상태 확인.

현재 범위:
- 한일 전환
- 한 업무의 5단계 실행 로드맵
- 단계별 이유·확인사항·공식 출처
- 막혔을 때 담당 창구에 가져갈 질문
- 사용자 준비 상태와 실제 기관 처리 상태의 구분

현재 하지 않는 것:
- 실제 신청 대행
- 개인 잔액 조회
- 실제 접수·지급 상태 조회
- 최종 자격 판정
- 생성형 AI 호출

첫 입력은 자연어처럼 보이지만 현재는 지원 시나리오 키워드를 확인하는 규칙 기반 데모다. AI를 연결할 때도 행정 요건·기관·기한을 모델이 생성하지 않고, 사용자의 상황 구조화와 쉬운 설명에 한정한다.

## 연구용 A/B 화면

research.html은 동일 정보를 정적 안내(A)와 준비 점검(B)으로 보여주는 비교 도구다. 기존 app.mjs, engine.mjs, 서초구 시술 전 준비 자료를 그대로 사용한다. 사용자 효과·시장 수요를 검증한 결과가 아니라 비교 실험을 위한 도구다.

## 클릭 가능한 제품 목업 — 2026-09-18

기본 제품 화면에 별도 `product.css`를 적용했다. 연구용 화면의 스타일·동작은 유지한다.

- 시작 화면: 상황 입력, 합성 예시, 지역·시술 전후 선택.
- 업무 확인: 해당 업무와 확인할 조건을 살펴본 뒤 시작.
- 실행 화면: 5단계를 순차 확인하고, 이미 확인한 단계는 다시 볼 수 있음.
- 도움 창: 현재 단계의 문의 문구 복사, 공식 담당 창구 전화 링크. 직접 전송하지 않음.
- 서류 화면: 준비 여부를 체크하고 언어·화면을 바꿔도 메모리에서 유지.
- 마지막 화면: 안내 확인 완료와 기관 접수·지급 미확인을 분리.

시연 순서: `약제비 지원받기` → `내가 할 일 알아보기` → `첫 단계 시작하기` → `도움이 필요해요` → 문의 복사 → 다음 단계 → 서류 체크 → 일본어 전환 → 마지막 단계.

다른 지역·시술 전·알 수 없는 상황과 지원하지 않는 문구는 자동으로 금천구 약제비 안내에 진입시키지 않는다. 이사 버튼은 지원 범위 밖이라는 안내를 표시한다. 자연어 이해 모델은 미연결이며 키워드와 선택 조건으로 합성 예시를 구분한다. 임의 자유문장의 정확한 분류를 보장하지 않는다.

검증: Chrome에서 입력 범위, 순차 진행, 문의 복사·닫기, 한일 전환과 체크 유지, 기관 상태 분리, 초기화, 데이터 로딩 실패, 연구 화면 회귀 및 모바일 가로 넘침을 확인했다. Node 13개·Python 9개 기존 검사를 통과했다. 실제 사용자·행정·번역 검토 결과는 아니다.

## 앱 UI 개편 · MY SEOUL+ 연결

- 480px 이하의 모바일 앱 레이아웃, 고정 하단 탭(홈·할 일·서류), 단계별 하단 실행 버튼.
- 소개 배너·사이드바·반복 설명 제거. 추가 근거는 펼침 영역, 구현 범위는 상단 `체험` 시트에 배치.
- 브랜드 표기를 `SeoulMate`로 통일. 한국어·일본어 화면과 체크 상태 유지.
- 도움 요청 시트에서 질문 복사·보건소 전화·MY SEOUL+ 통역·상담 안내로 이동.
- MY SEOUL+는 공개 외부 링크이며 공식 제휴·자동 전송·API 연동이 아니다. 일본어 화면의 문의에는 한국어 문구도 함께 제공한다.
- 후속 협력 범위와 발표 제안: [MY SEOUL+ 연계안](../docs/17-my-seoul-integration.md).

## 서울톡 지식 연계 채팅 목업

하단 `채팅` 탭을 추가했다. 기존 홈·할 일·서류와 함께 사용한다.

- 질문 언어 자동 선택 또는 한국어·일본어·영어 답변 지정. 화면 언어와 답변 언어는 별개다.
- 약제비·공공시설 예약·통역 지원 질문, 약제비 서류·잔액 후속 질문.
- 출처·확인일·한국어 기준 답변 펼침과 다음 행동 버튼.
- 예시 질문 → 답변 언어 `English` → `필요한 서류는?` → 준비 절차로 이동하는 흐름을 시연할 수 있다.
- 실제 서울톡 자료는 미제공 상태다. `chat.mjs`의 공개 자료 기반 고정 예시를 사용하며 DB·API·LLM·실시간 번역은 미연결이다. 범위 밖 질문에는 미지원 답변을 표시한다.
- 입력·기록은 메모리에서만 유지되며 외부 전송 없이 새로고침 시 초기화된다.
- [연계 가정·시연·정책 요청](../docs/18-seoul-talk-chat.md).

검증: 언어 선택 우선순위, 후속 질문 맥락, 잔액 미조회, 근거 없는 답변 방지 등 Node 테스트와 모바일 채팅·언어 전환·탭 이동·진행 중 새 대화·준비 절차 연결을 브라우저에서 확인했다.

## SeoulMate · 생활 FAQ / 공문 QR / 문서 읽기

서비스 이름을 SeoulMate로 통일했다. [팀의 기존 서비스](https://seoulmate.ai.studio/)에서 공문 QR → 다국어 행동 안내, 문서 이해, 생활 사건별 체크리스트 흐름을 참고하고 기존 앱 디자인에 맞췄다.

- 홈의 `생활 FAQ`: 이사, 퇴직금, 임금 체불, 이직, 체류기간 연장, 통역 지원 6개. 생활·직장·체류 필터, 한국어·일본어·영어 안내, 준비 체크, 공식 출처, 상담 창구, 채팅 연결.
- 이사 기한은 등록외국인 15일과 국내거소신고자 14일을 구분한다. 퇴직금은 근로 요건 및 지급기일 연장·출국만기보험에 따른 확인 사항을 함께 안내한다. 개별 자격·금액·체류 허가는 판단하지 않는다.
- `문서 읽기`: 준비된 한국어 이사 안내문에서 선택 언어의 요약·기한·할 일·준비 자료로 이동하는 녹화용 시연. 사진 촬영·선택과 로컬 미리보기는 지원하며, 실제 OCR은 연결하지 않았다.
- `공문 QR`: 안내 및 언어 선택 → 실제 SVG QR 생성 → 링크 복사 / SVG 저장 / 주민 화면 열기. 안내 URL은 `index.html#guide=moving&lang=ja` 형태의 고정 ID를 사용한다. 같은 경로에 배포하면 별도 서버 라우팅 없이 직접 진입한다.
- QR은 현재 서비스 주소를 사용한다. localhost에서 생성한 QR은 다른 기기에서 접속할 수 없으며 화면에도 이를 표시한다. 공개 배포 후 해당 주소에서 다시 생성해야 한다. 실제 영구 게시·관리 서버나 개인 데이터는 없다.
- QR은 로컬 번들 `vendor/qrcode.mjs` (qrcode-generator 2.0.4, MIT)로 생성한다. 외부 QR 서비스에 URL을 전송하지 않는다.

녹화 예: 생활 FAQ → 이사 → 일본어 안내·체크리스트 → 안내 QR 생성 → 주민 화면 열기. 또는 문서 읽기 → 일본어 선택 → 쉬운 안내로 보기.

검증: 생성 QR을 디코딩해 안내 URL 일치 확인, 링크 복사·SVG 다운로드·새 창 직접 진입·새로고침, 언어 변경, FAQ 필터와 준비 체크, 채팅 연결, 320~1440px 가로 넘침을 확인했다.

## 쉬운 용어 설명과 지역 기준 채팅

[maakcode/seoul-mate](https://github.com/maakcode/seoul-mate)의 출처·확인일 표시, 진행 안내, 중지·재시도 흐름을 참고했다. 레이아웃·색상·타이포그래피는 이 프로젝트의 앱 테마를 유지한다. 답변을 짧은 단락, 쉬운 용어 카드, 지역 문의 카드, 펼쳐 보는 행동·출처로 나눈다.

- `내 지역 설정`에서 금천구·마포구·강남구를 직접 선택한다. GPS나 좌표를 수집하지 않는 목업이며 다음 질문부터 반영한다.
- 체류지 변경신고·국내거소신고·소정근로시간·퇴직금·진정·체류자격·원외처방·지원 잔액을 한국어 공식 명칭과 선택 언어의 쉬운 설명으로 제공한다.
- 금천구 이외 지역의 약제비 질문에는 금천구 절차·기한·전화번호를 그대로 적용하지 않는다. 노동 상담은 거주지가 아닌 사업장 소재지에 따라 관할을 확인하도록 한다.
- 답변 진행 중 `중지`, 중지 후 `다시 시도`를 지원한다. 새로운 답변은 첫 문단부터 보이도록 스크롤한다.
- 질문·지역·키는 외부로 전송하지 않는다. GPS, 실제 API 검색, 실시간 번역은 미연결이다.

### API 키 준비

루트 `.env`에 `OPENAI_API_KEY`, `SEOUL_API_KEY`를 저장할 수 있다. `.env.example`은 빈 예시이고 `.env`는 Git에서 제외된다. 미리보기는 `scripts/serve_preview.py`로 실행한다. 저장소 루트를 일반 정적 서버로 제공하면 `.env`가 노출될 수 있으므로 사용하지 않는다.

현재 프런트엔드는 녹화용 고정 답변을 사용하며 키를 읽지 않는다. 키를 저장해도 API가 자동 호출되지 않는다. 실제 연계 시 서버 전용 코드에서만 환경변수를 읽도록 연결해야 한다. 키를 JS·HTML·브라우저 저장소에 넣지 않는다.

시연: 채팅 → 내 지역 설정 `마포구` → `引っ越しました。住所変更はどう届け出ますか？` → 일본어 안내·용어 설명 → 마포구 문의 안내 → 공식 출처 확인.

## 홈의 문서 촬영

홈 `문서 촬영` → `사진 촬영` 또는 `사진에서 선택` → 미리보기 → 번역 언어 선택 → `분석 결과 예시 보기`.

- 휴대폰에서는 HTML의 `capture="environment"` 입력으로 카메라 촬영을 요청하고, 사진 선택 입력도 별도로 제공한다. 실제 카메라 제공 방식은 OS·브라우저에 따른다. 데스크톱에서는 파일 선택 창을 사용한다.
- 이미지는 로컬 object URL로 표시한다. 15MB 이하의 지원되는 이미지 형식을 받고, 열 수 없는 형식은 다시 선택하도록 한다. 파일명·이미지·문서 내용을 서버로 전송하거나 저장하지 않는다. 삭제·교체 시 URL을 해제하고 새로고침하면 사라진다.
- 실제 OCR·이미지 분석 API는 연결하지 않았다. 업로드한 사진의 분석 결과처럼 표시하지 않고, 이사 안내문 샘플이라는 문구를 입력 확인과 결과 화면에 표시한다.
- 결과 예시는 문서 요약, 확인 대상, 기한, 한국어·일본어·영어의 쉬운 번역, 다음 행동, 준비 자료, 한국어 샘플 원문, 공식 근거와 상담 창구로 구성된다. 이어서 기존 체크리스트로 이동한다.
- 사진이 없어도 `사진 없이 샘플로 체험`으로 동일 흐름을 녹화할 수 있다.

브라우저에서 카메라 입력 속성·파일 선택, 이미지 미리보기, 잘못된 파일 거절, 언어 전환, 예시 결과 표시, 체크리스트 연결, 사진 초기화, 320~1440px 레이아웃과 외부 이미지 전송 없음을 확인했다. 실제 휴대폰 카메라 하드웨어 동작은 데스크톱 검증 범위 밖이다.
